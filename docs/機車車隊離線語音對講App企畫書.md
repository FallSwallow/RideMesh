# 機車車隊離線語音對講 App 企畫書（初版）

版本：0.3｜日期：2026-09-27｜狀態：技術可行性驗證前

## 一、企畫摘要

開發供最多五名機車騎士使用的 Android／iOS 語音對講 App。騎士各自使用手機與已配戴的藍牙安全帽耳機；手機之間直接傳送語音，不依賴行動數據、網際網路、雲端服務或額外架設的伺服器。每支手機都是平等的通訊節點，可主動尋找、接受連線及轉送語音，沒有固定主持手機。目標是在視線可及、兩車相隔 100 公尺內直接通話；超出直接連線能力時，仍能與前後可連到的成員自動維持通訊。騎士在出發前完成組隊，騎乘時即使手機鎖屏，也能透過耳機持續交談。

**目前結論：**這是值得做實機原型的方向，但「跨 Android／iOS、兩車直連 100 公尺、五人動態自連與轉送、全部鎖屏、移動中穩定通話」尚不能只憑平台文件保證。100 公尺直連及動態鄰居連線應分開驗收；應先通過雙機與三機斷鏈實測，再投入完整 App 開發。

## 二、已確認需求

| 項目 | 需求 |
| --- | --- |
| 使用者 | 同一車隊，最多五人 |
| 距離 | 目標為視線可及、最遠兩車相隔 100 公尺內 |
| 裝置 | Android 或 iPhone；每人已有藍牙安全帽耳機 |
| 使用方式 | 出發前啟動，騎乘時免看手機、免按螢幕，鎖屏後持續通話 |
| 通訊 | 手機對手機直連；騎乘時不依賴外部伺服器或網際網路 |
| 連線方式 | 每支手機同時具備發現、接受連線、發話、收話及轉送能力；無固定主機 |
| 失聯行為 | 遠端成員斷線時，仍可與前後可連到的成員通話；兩段重新靠近後自動合併 |
| 功能範圍 | 第一版只做即時群組語音 |

安裝 App、更新及首次下載所需的網路，不屬於騎乘時的通訊路徑。部分 Android 近距離連線 API 仍要求宣告 `INTERNET` 權限，這不代表語音必須送上網；App 應實測並明確揭露騎乘時的資料流向。[Android Wi‑Fi Aware 文件](https://developer.android.com/develop/connectivity/wifi/wifi-aware)

## 三、使用流程

1. **出發前：**每位騎士先將安全帽耳機與自己的手機配對。建群者在 App 建立臨時車隊，其他人於停車狀態加入並完成手機間的安全配對。
2. **確認通話：**App 顯示每位成員、耳機音訊路徑及連線狀態；所有人做一次收發話測試，再按「開始對講」。
3. **騎乘中：**使用常駐的語音通話模式；有人說話時自動傳送語音，其他人從安全帽耳機收聽。每支手機持續維護可連到的群組成員：遠方成員斷線時，前後仍可相連的手機繼續通話；需要時由中間手機轉送語音。兩段車隊重新靠近時，自動恢復跨段連線並合併通話。
4. **結束：**停車後手動結束群組通話。第一版不錄音、不保留語音內容。

不把「安全帽耳機上的按鈕可控制 App」列為第一版必要功能；各品牌按鈕事件的支援情況需要另外驗證。

## 四、技術架構草案

**音訊路徑：**安全帽麥克風 → 藍牙免持音訊 → 手機 App → 一個或多個手機間直連路徑 → 其他手機 App → 藍牙安全帽耳機。

**去中心化規則：**每支手機同時對同群成員提供連線與搜尋功能，不指定永久主持手機。手機自動連到當下可達的其他成員；App 依連線品質維護鄰居與路徑。最前與最後的手機即使無法直接相連，只要中間成員形成連續路徑，語音便可逐段轉送。音訊封包須具備來源、序號、存活跳數與重複封包辨識，避免轉送循環和重複播放。若整個車隊分裂成互不連通的兩段，兩段各自維持內部通話；沒有無線路徑時，無法跨段傳送即時語音。所有轉送與重連都以手機 App 完成，不使用外部伺服器。

| 層次 | 初步方案 | 需驗證事項 |
| --- | --- | --- |
| 手機間連線 | 優先試作 Wi‑Fi Aware；不需要路由器或網際網路 | iPhone／Android 實際配對、雙機在 20／50／100 公尺及移動時的穩定性 |
| 群組拓樸 | 所有手機都可發現與接受連線；自動維護當下可達的鄰居，能直接送達就直送，否則由中間手機逐段轉送 | 各手機可同時維持的連線數、路徑切換、轉送延遲及鎖屏穩定性 |
| 斷線與合併 | 每段仍相連的車隊獨立通話；恢復接觸後自動重建鄰居連線與跨段語音路徑 | 分裂、重連、合併時是否有重複播放、失聲或短暫音訊突波 |
| 語音 | Opus 編碼、語音活動偵測、短緩衝與封包遺失補償 | 安全帽耳機與騎乘風噪下的可懂度及延遲 |
| 安全 | 系統層配對，加上 App 層群組身分驗證與會話金鑰 | 陌生裝置加入、成員退出後的金鑰更新 |

Wi‑Fi Aware 是跨平台標準，但**跨廠牌互通仍須由目標機型證明**。iPhone 端的基本門檻是 iOS 26 與 iPhone 12 以上；Android 必須檢查 Wi‑Fi Aware 硬體支援、當下可用狀態及可用連線資源。[Apple Wi‑Fi API 說明](https://developer.apple.com/documentation/technotes/tn3111-ios-wifi-api-overview) · [Android Wi‑Fi Aware 文件](https://developer.android.com/develop/connectivity/wifi/wifi-aware)

若 Wi‑Fi Aware 在目標機型上不可行，第二候選是支援 Android／iOS 且不要求網際網路的 Nearby Connections；它的鎖屏、長時間語音及五人運作同樣須重新實測。[Google Nearby Connections](https://developers.google.com/nearby)

## 五、鎖屏與耳機的設計重點

- **iOS：**正在進行的收發話應使用適合雙向通訊的音訊設定與背景音訊能力；配對的安全帽耳機須作為麥克風及揚聲器。Apple 文件說明此類音訊可在鎖屏後持續，但若 App 被暫停、系統終止、來電打斷或無線連線失效，不能預設附近封包會自行喚醒並修復通話。[iOS 背景音訊](https://developer.apple.com/documentation/avfaudio/avaudiosession/category-swift.struct/playandrecord) · [藍牙 HFP 音訊](https://developer.apple.com/documentation/avfaudio/avaudiosession/categoryoptions-swift.struct/allowbluetoothhfp)
- **Android：**在 App 可見時由騎士啟動通話與麥克風前景服務；需處理新版 Android 對背景啟動麥克風服務的限制，並正確選擇耳機作為通訊音訊裝置。[前景服務限制](https://developer.android.com/develop/background-work/services/fgs/service-types) · [音訊裝置選擇](https://developer.android.com/reference/android/media/AudioManager)
- **兩平台：**監聽來電、耳機斷線、音訊路徑切換、Wi‑Fi Aware 不可用及手機過熱等事件；清楚提示目前「可收發話」「正在重連」或「無法通話」。

## 六、第一版功能範圍

**納入：**最多五人建群／加入、出發前音訊檢查、免按鍵群組語音、鎖屏持續通話、每支手機自動發現與接受鄰居連線、跨手機語音轉送、連線分裂後各段持續通話與自動合併、成員與連線狀態、失聯提示、手動靜音、安全配對。

**暫不納入：**地圖與定位、文字聊天、錄音、雲端帳號、對外撥號、與其他對講機或耳機品牌的專用互通、緊急救援保證。音樂與導航語音的混音行為需在原型中觀察，再決定是否列入正式版本。

## 七、分階段驗證與交付

| 階段 | 工作 | 通過條件／交付物 |
| --- | --- | --- |
| 1. 裝置盤點 | 蒐集預計使用的 iPhone、Android 與安全帽耳機型號；檢查 Wi‑Fi Aware 與耳機通話音訊能力 | 支援機型清單、不能支援的機型清單 |
| 2. 雙機技術原型 | 一支 iPhone 與一支 Android 完全離線配對、雙向通話、兩機鎖屏，分別測 20／50／100 公尺 | 實際錄下連線、音訊、延遲與恢復數據；100 公尺雙機直連是距離需求的第一道驗收門檻 |
| 3. 三機斷鏈原型 | A、B、C 三支手機各自可搜尋並接受連線；讓 A 與 C 無法直連，但 A↔B、B↔C 可連 | A 與 C 可經 B 收發語音；移除 B↔C 後 A、B 仍能通話；恢復接觸後三機自動合併 |
| 4. 五人群組原型 | 擴充至五支手機，測任意一支離隊、兩段分裂與重新合併；測車隊頭尾相隔 100 公尺 | 無固定主機；各連通區段可持續通話，恢復可達時自動重建跨段通話 |
| 5. 騎乘情境測試 | 在安全且受控的場地測移動中的 20／50／100 公尺、不同手機擺放位置、全部鎖屏、耳機與來電中斷 | 問題清單、裝置相容性矩陣、正式版範圍與時程估算 |

**建議測試目標，非已保證性能：**兩人直連在視線可及的 100 公尺仍可雙向通話；單段直連語音端到端延遲以 500 毫秒內為目標，多段轉送須另外量測；在重新進入有效距離後，以 5 秒內恢復鄰居連線為目標；五人車隊頭尾相隔 100 公尺且全部鎖屏，連續測試至少一小時，並記錄掉線、耗電、溫度及語音可懂度。測試必須包含 A↔B↔C 可通而 A↔C 不可直連、分裂成兩段及重新合併的情境。若雙機在 100 公尺無法直連，中間手機轉送只能滿足有其他成員可作橋接的情境，不能視為已滿足雙人 100 公尺需求。若任一目標在主要機型上無法達成，應先調整裝置支援範圍或產品承諾，再進入正式開發。

## 八、主要風險與決策點

1. **跨平台配對失敗：**標準互通不等於所有手機已可互通；雙機原型應最先驗證。
2. **鎖屏後無法維持或恢復：**這是產品成立的核心門檻；不能以播放靜音或一般背景排程代替真正的通話生命週期。
3. **多連線與轉送資源不足：**手機可同時維持的 Wi‑Fi Aware 路徑數可能不同；各成員都要能擔任中間轉送節點，並測鎖屏下多路連線、發熱及耗電。
4. **風噪與耳機差異：**不同安全帽耳機的麥克風、藍牙協定及降噪效果不同；至少用實際預計採用的耳機型號測試。
5. **距離、移動與電量：**100 公尺的視線距離不保證手機間的實際訊號品質；手機在口袋、車架或外套內，以及長時間同時使用 Wi‑Fi 與藍牙，都可能影響連線、發熱與電量。中間手機轉送也會增加延遲與耗電。
6. **分裂時無法跨段通話：**兩段車隊若沒有任何手機間無線路徑，App 只能讓各段內部繼續通話；這是離線直連的物理限制，應在介面與語音提示中明確反映。
